This mailpit checkout carries one main graded defect in `IsInternalIP` in `internal/tools/net.go`, the check the link checker, the CSS/HTML checker and the asset proxy use to refuse connections to internal destinations. It recognises IPv4 internal ranges and the IPv6 ranges Go's `net.IP` methods know, but an IPv6 address that carries an internal IPv4 address (NAT64 well-known or local-use, 6to4, IPv4-compatible, Teredo or ISATAP forms) and the IPv6 site-local and documentation prefixes are reported as external, so those features connect to loopback, private or link-local destinations when given such an address.

The checkout also carries a second access-control weakness that earns a small share: the cross-origin check in `middleWareFunc` in `server/server.go` decides on the raw request target (`r.RequestURI`) while the router dispatches on the percent-decoded path, and the WebSocket upgrader in `server/websockets/client.go` accepts every origin, so a request from a foreign origin to a percent-encoded API, events or HTML preview path skips the origin check.
