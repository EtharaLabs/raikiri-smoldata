This fast-uri checkout carries its main graded defect in the mailto scheme handler in `lib/schemes.js`. When a `mailto:` URI is parsed, a query field name is compared with `to`, `subject` and `body` before it is percent-decoded and with exact letter case, so names such as `%74o`, `%73ubject` or `TO` are kept as generic headers; when the component is serialized, a decoded field name that contains a percent sequence is written out so that the next parse decodes it again. The recipients, subject, body and headers a caller sees after parsing can therefore differ from what the same URI yields after it is serialized and parsed again.

The agent was given only the vulnerable source tree and a statement naming the broad weakness family, and returned two deliverables. D1, `/output/fe22839e-5022-5dd9-9220-65b16c728a04_D1_reproducer.patch`, is a reproducer that adds or changes test files only. D2, `/output/fe22839e-5022-5dd9-9220-65b16c728a04_D2_repair.patch`, is the repair. Only D2 sections on `lib/schemes.js` and `index.js` are applied when the repair is graded; sections on any other file, including `lib/utils.js`, are dropped, and a D2 that changes nothing in those two files delivers no repair. The D2 sections on `index.js` are graded only as a repair of the second, smaller weakness: the domain-host canonicalization adopts the WHATWG parser's rewrite of a host that holds raw whitespace or a second `@`.

The rubric judges the state change D2 makes to `mailtoParse` and `mailtoSerialize` in `lib/schemes.js`: whether field names are classified by their decoded, case-folded spelling, whether a percent sign in a generic field name is serialized as data, whether reserved spellings of any case in serialized headers are folded into the dedicated fields, whether legitimate mailto behavior is preserved, and whether the change is written the way the module is written. A repair that corrects only one direction leaves the defect open. The evidence is the D2 diff itself, not the agent's description of it.
