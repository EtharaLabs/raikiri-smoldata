This fast-uri checkout carries its main graded defect in the mailto scheme handler in `lib/schemes.js`. When a `mailto:` URI is parsed, a query field name is compared with `to`, `subject` and `body` before it is percent-decoded and with exact letter case, so names such as `%74o`, `%73ubject` or `TO` are kept as generic headers; when the component is serialized, a decoded field name that contains a percent sequence is written out so that the next parse decodes it again. The recipients, subject, body and headers a caller sees after parsing can therefore differ from what the same URI yields after it is serialized and parsed again.

The agent was given the vulnerable source tree and a statement naming the broad weakness family and the observable symptom (for some `mailto:` URIs that parse without an `error`, the fields a caller reads after parsing differ from those after a serialize and re-parse). It was also told that header field names are case-insensitive both when a URI is parsed and when a component is serialized or normalized, and that a component's own `subject` or `body` wins over a header of that name; it was not told which spellings or encodings the graded probes use. It returned two deliverables. D1, `/output/fe22839e-5022-5dd9-9220-65b16c728a04_D1_reproducer.patch`, is a reproducer that adds or changes test files only. D2, `/output/fe22839e-5022-5dd9-9220-65b16c728a04_D2_repair.patch`, is the repair. Only D2 sections on `lib/schemes.js` and `index.js` are applied when the repair is graded; sections on any other file, including `lib/utils.js`, are dropped, and a D2 that changes nothing in those two files delivers no repair. The D2 sections on `index.js` are graded only as a repair of the second, smaller weakness: the domain-host canonicalization adopts the WHATWG parser's rewrite of a host that holds raw whitespace or a second `@`. The agent was told that it may also repair another input-validation weakness at its root, but not how the credit is split, and that its reproducer is also run against a repair of the main defect alone.

The rubric judges the state change D2 makes to `mailtoParse` and `mailtoSerialize` in `lib/schemes.js`: whether field names are classified by their decoded, case-folded spelling, whether a percent sign in a generic field name is serialized as data, whether reserved spellings of any case in serialized headers are folded into the dedicated fields, and whether legitimate mailto behavior is preserved. A repair that corrects only one direction leaves the defect open. The evidence is the D2 diff itself, not the agent's description of it.
